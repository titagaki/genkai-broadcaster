# Genkai Broadcaster 仕様書 (v0.0.1)

Android RTMP配信アプリの仕様定義。
実装の基準とし、仕様変更時は本書を更新する。

- 対象バージョン: v0.0.1 (`versionName`。初期リリース)
- 最終更新: 2026-09-13

## 1. 概要・目的

スマートフォンのカメラ映像とマイク音声を、ユーザーが指定したRTMPサーバーへ
push配信するAndroidアプリ。

- 用途: 任意のRTMP受信環境へのスマホ起点のライブ配信
- 対応先の例: 一般的なRTMPサーバー、PeerCastStation、PeerCast Gateway
- 製品位置づけ: PeerCastでの利用を想定するが、PeerCast専用・特化にはしない
- 方針: 余計な機能を持たせず「起動→URL/キー入力→配信開始」の最短動線に絞る
- 非目標: SRT 配信、チャット表示、OBS連携、マルチプラットフォーム同時配信、録画保存 (対象外)

## 2. スコープ

### 2.1 対応

| # | 機能 | 概要 |
|---|------|------|
| F-01 | カメラプレビュー | 送信解像度の比率でフレーム全体を表示 (レターボックス、`AspectRatioMode.Adjust`) |
| F-02 | RTMP配信 開始/停止 | 選択中の接続先 (サーバーURL + ストリームキー) へ push |
| F-03 | 複数接続先 | 接続先 (名前 + サーバーURL + キー) を複数保存し切り替え。入力例: PeerCast Gateway / Twitch |
| F-04 | 解像度選択 | 360p / 480p / 720p / 1080p。停止中のみ変更可 |
| F-04b | フレームレート選択 | 15 / 24 / 30 / 60 fps (既定 30)。停止中のみ変更可 |
| F-04c | エンコーダ選択 | 互換 (ソフトウェア) / 標準 (ハードウェア)。既定は互換。停止中のみ変更可 |
| F-05 | ビットレート調整 | 100〜10000 kbps、配信中の on-the-fly 変更可 |
| F-06 | カメラ切替 | `FRONT` / `BACK`を明示選択 (配信中可) |
| F-07 | マイクミュート | 配信中・プレビュー中のミュート切替 |
| F-08 | 自動再接続 | 切断時に5秒間隔・最大10回リトライ |
| F-09 | ステータス表示 | 小さい接続状態、経過時間、送信ビットレート (平滑値 Mbps) + スループット判定 |
| F-10 | 設定保存 | 接続先一覧・選択中の接続先・映像方向・解像度・FPS・ビットレート・エンコーダ種別を端末保存 |
| F-11 | バックグラウンド継続 | ForegroundService + 通知 (停止ボタン付き、タップでアプリへ戻る) |
| F-12 | カメラ・倍率選択 | 配信ボタン左の`BACK・1x`形式のセレクターからカメラ面と利用可能な倍率を選択 |
| F-13 | 音量メーター | マイク入力レベルを10セグメントで表示。配信前のプレビュー中から動作 |
| F-14 | 電池残量表示 | 情報表示の2行目に残量% + 充電状態を表示 (30秒ごとに更新) |
| F-15 | 縦配信・横配信切替 | 停止中に縦長 (9:16) / 横長 (16:9) を選択、画面の向きも連動 |
| F-16 | ピンチズーム | 連続倍率変更。論理マルチカメラか物理レンズ固定かはUIへ露出しない |
| F-17 | 使用マイク表示 | メーター下に使用中と推定されるマイク種別 (内蔵 / 有線 / USB + 製品名) を表示。抜き差しで更新。選択機能は持たない |

### 2.2 非対応 (対象外)

- SRT / RTSP / WHIP 等、RTMP 以外の配信プロトコル
- チャット・コメント表示、ブラウザソース/オーバーレイ (将来候補あり)
- 配信中の出力解像度・縦横比・FPS・エンコーダの変更 (切替には配信停止が必要)
- 録画保存、ライト (トーチ)、マイクの明示選択、Bluetooth マイクの検出

## 4. 配信フォーマット

エンコードは H.264 (映像) + AAC-LC (音声) に固定し、
幅広いRTMP受信環境とデコーダーでの互換性を優先する。
コーデック選択UIは持たない。

| 項目 | 設定 | 備考 |
|------|------|------|
| 映像コーデック | H.264 (`VideoCodec.H264` を明示) | |
| プロファイル | Constrained Baseline を指定 (`AVCProfileConstrainedBaseline`) | ヒント扱いで、HW エンコーダによっては constraint_set1_flag が立たず素の Baseline になる (DXVA2 非対応)。詳細は [PeerCast接続ガイド](../integrations/peercast.md) |
| エンコーダ | 互換 (既定): ソフトウェア (`CodecType.SOFTWARE`、AOSP `c2.android.avc.encoder`) / 標準: HW 優先 (`FIRST_COMPATIBLE_FOUND`) | 互換は constraint_set1_flag が確実に立ち、DXVA2 経路の PC プレーヤーで再生できる。CPU 負荷・電池消費は増える。音声エンコーダは常に `FIRST_COMPATIBLE_FOUND` |
| Level | 解像度・FPSから自動選定 (`H264Level`) | MaxMBPS基準 (720p30→3.1、720p60→3.2、1080p30→4.0、1080p60→4.2)。過剰なLevelを付けない |
| キーフレーム間隔 | 2秒 (`iFrameInterval=2`) | 途中参加時の復帰を早くする |
| 音声コーデック | AAC-LC (`AudioCodec.AAC` を明示。HE-AACではない) | |
| 音声パラメータ | 32 kHz / ステレオ / 128 kbps | 固定。UI は持たない |
| FPS | 15 / 24 / 30 / 60 から選択 (既定 30) | 60 はカメラが対応しない端末では実効 30 になる。Level は選択FPSで再計算 |
| 出力方向 | 横: rotation=0 / 縦: rotation=90 | カメラ入力の幅・高さは横長のまま渡し、縦出力時はライブラリがエンコード幅・高さを交換 |

## 5. 配信プロトコル仕様

- 方式: RTMP push のみ。URLスキーム `rtmp://` 以外は受け付けない (前方一致で判定。それ以上の URL 検証はしない)
- フルURLの組み立て: `サーバーURL(末尾/除去) + "/" + ストリームキー(前後/除去)`
  - キー空欄時はサーバーURLをそのまま使用
  - 接続先が1件も無ければ空文字となり、不正URLとして開始を拒否する
- 受信側の準備方法や認証方式は接続先の仕様に従う
- PeerCastStation / PeerCast Gateway固有の手順は[PeerCast接続ガイド](../integrations/peercast.md)を参照
- 再送・ボンディング等の回線対策は持たない (単一RTMPコネクション)

## 6. 画面仕様

画面は「配信画面」「設定画面」の2画面構成。
黒・ダークグレー基調のカメラ操作UIとし、開始は緑、停止・ミュートは赤系で区別する。
カメラプレビュー領域と操作帯を分け、情報表示・設定・音量メーターだけをプレビュー上へ重ねる。
操作帯は陸上トラックのようなスタジアム形 (平行線 + 両端の半円) で、縦配信では下、横配信では右に置く。
設定類は右上の歯車から開く設定画面にまとめる。

### 6.1 配信画面レイアウト

```
縦画面
+----------------------------------+
| 状態 / 720x1280 / 30fps   [設定] |
| 時間 / 送信統計 / 電池%          |
|                                  |
|            (プレビュー)          |
|                                  |
| 音量                             |
| マイク種別                       |
+----------------------------------+
| (  [BACK・1x]   (開始)  (マイク) ) |  ← 操作帯 (スタジアム形)
+----------------------------------+

横画面
+------------------------------------------+-------+
| 状態 / 解像度 / FPS               [設定] |  ( )  |
| 時間 / 統計 / 電池%                      | BACK  |
|                                          |  1x   |
|             (プレビュー)                 | (開始) |
|                                          |(マイク)|
| 音量 / マイク種別                        |  ( )  |
+------------------------------------------+-------+
                                            ↑ 操作帯 (縦のスタジアム形)
```

### 6.2 配信画面UI要素仕様

- プレビュー: `SurfaceView` をプレビュー領域いっぱいに配置し、情報表示の背面で表示する。操作帯とは重ねない。
- 操作帯: スタジアム形 (`CircleShape` を矩形に適用) の半透明ダーク面。縦配信では画面下に横長、横配信では画面右に縦長で置き、
  帯を3等分したスロットにカメラ・倍率セレクター、配信開始・停止、マイクを置き、配信開始・停止を帯の中心に揃える。
- 左下に音量メーター (10セグメント、下から緑5・黄3・赤2。ミュート時は消灯) を下端に沿わせて表示。
  100ms ごとにピークを読み、減衰させながら表示する。プレビュー中はマイクだけ起動して配信前から反応する。
- メーターの下に使用中と推定されるマイク種別を小さく1行表示する (`内蔵マイク` / `有線マイク (製品名)` / `USB マイク (製品名)`、
  判定不能なら `マイク不明`)。
  アプリはマイクを明示選択せず OS のルーティングに任せるため、接続中の入力デバイスから AudioPolicy の優先順
  (有線 > USB > 内蔵) で推定する (`system/MicrophoneMonitor`)。Bluetooth は対象外。
  プレビュー停止 (バックグラウンド等) 時はマイクも止める。
- 未準備時はプレビュー中央に案内 (`プレビュー準備中`、またはカメラエラー文) を表示し、必須権限がなければ
  `カメラ・マイクを許可` ボタンを添える。プレビュー準備前は配信開始・マイク・カメラセレクターを無効にする
  (カメラエラー時はセレクターだけ有効にして、別カメラへの切替で復帰できるようにする)。
- 左上に状態・出力寸法・FPSを1行 (`待機中 / 1280 x 720 / 30 fps`) で小さく表示し、その下に経過時間・送信統計・電池残量を
  ` / ` 区切りで表示する。`待機中`・`LIVE`・`切断`等を大きなバッジにはしない。長い文は1行で省略する (最大幅 320dp)。
  経過時間は `mm:ss`、1時間を超えると `hh:mm:ss`。送信統計は `x.x Mbps [スループット判定]`。
- 右上に設定の丸ボタンをプレビューへ重ねる。配信開始・停止とマイクは操作帯内の同サイズ (52dp) の丸ボタンで、
  開始は緑・停止は赤・ミュート中のマイクは赤。画面高さ 400dp 未満では各ボタンを 44dp に縮小し、操作ラベルを隠す。
- 配信方向 `[縦 9:16] [横 16:9]` は設定画面だけに置く。停止中のみ選択可で、接続中・再接続中もロックする。
- 操作帯の先頭に`BACK・1x`形式のピル型セレクターを表示する。ポップアップは`CAMERA`行の
  `FRONT` / `BACK`と、`ZOOM`行の利用可能な倍率で構成し、パネル外タップで閉じる。
  倍率は整数なら `2x`、そうでなければ小数1桁 (`1.5x`) で表示する。
- プレビューの2本指ピンチで、端末が公開する範囲内の倍率を連続変更する (プレビュー準備前は無効)。
  Android 11以降で論理マルチカメラが公開されている背面カメラは、倍率によるレンズ切替を優先する。
  非対応端末では倍率に対応する物理レンズへ固定し、そのレンズ内のデジタルズームを使う。
- 倍率は標準画角を`1x`として正規化する。同じ実レンズ・倍率になる重複カメラIDは1項目へまとめ、
  論理カメラ・物理レンズ・`自動`等の内部方式は通常UIへ表示しない。
- カメラ・物理レンズ切替は新しいCaptureSessionの最初のフレームで成功を確定する。
  各段階で5秒以内にフレームが来なければ失敗とする。カメラエラー・切断時はプレビューを未準備に戻して
  失敗理由を表示し、配信中なら映像が不定のまま送信を続けず配信を停止する。
- デバッグ可能なAPKでは設定画面から自動判定・デジタル強制・論理カメラ強制を切り替え、
  APIレベル・カメラID・倍率範囲を確認できるようにする。
- マイクはON/OFFとも丸ボタンとし、アイコン・色・小さいラベル (`ON` / `OFF`) で状態を示す。ライト機能は持たない。
- 配信開始は緑、停止は赤の丸ボタン。接続中・再接続中も停止操作は可能。
- 不正URL等の注意文は左上の小さい状態表示に出す。操作はシステムバー・画面切り欠きの安全領域を避ける。
- streamer 層からの一時的な通知文 (配信開始、再接続、失敗理由など) は Toast で表示する。どの画面でも同じ。

### 6.3 設定画面UI要素仕様

- カテゴリメニュー → 各ページの2階層構成 (配信ページだけ接続先の編集で3階層目)。
  メニューは `配信` `映像` `カメラ` `権限` の行を縦に並べ、
  各行に現在値の要約 (接続先名 + キー有無、向き/解像度/FPS/ビットレート/エンコーダ) を表示する。
  `カメラ` はデバッグ可能なAPKだけ表示する。
- タイトルバー (戻るボタン + ページ名 + 補足)。メニューでは「設定」+ 自動保存の案内、編集ページでは接続先名 + 「接続先の編集」。
  戻るボタン・端末の戻るボタンは編集 → ページ → メニュー → 配信画面の順に戻る。
- 配信処理中 (接続中・LIVE・再接続中) は、権限ページ以外の上部に
  「配信処理中です。ビットレート以外の映像・接続設定は、停止後に変更できます。」を表示する。
- 配信: 接続先の一覧 (ラジオで選択、鉛筆で編集。副題にサーバーURLとキー有無) と追加ボタン
  (`PeerCast Gateway` / `Twitch` / `空の接続先`)。
  追加すると3階層目の編集ページに入り、名前・RTMPサーバーURL・ストリームキーを編集する (入力は即時保存)。
  キーは既定でマスクし、表示/非表示を切替可能。最後の1件は削除できない。
  選択中の接続先を削除した場合は先頭の接続先を選択中にする。
- 映像: 配信方向の選択と持ち方の案内文、一般的な呼び名と実際の出力寸法を併記した解像度ドロップダウン
  (例: `HD (720p) / 1280 x 720`、縦配信なら `720 x 1280`)、フレームレートのセグメント選択 (15/24/30/60)、
  ビットレートの数値入力 + 右端の ∧/∨ ボタン (100〜10000 kbps、100 kbps刻み)、
  エンコーダのラジオ選択 (`互換 (ソフトウェア)` / `標準 (ハードウェア)`、ズーム方式と同じ縦並びの OutlinedButton + RadioButton) と選択に応じた説明文。
  ビットレートは入力中も範囲内の値だけを即時反映し、範囲外はエラー表示に留める。フォーカスが外れた時と IME の完了で範囲内に丸めて確定する。
- カメラ (デバッグAPKのみ): ズーム方式の強制切替と診断表示 (`API xx / camera id / モード / 倍率範囲`)。
- 権限: 権限再確認ボタンのみ (接続先ごとの準備案内は置かない。手順は [PeerCast接続ガイド](../integrations/peercast.md) 等の文書に置く)。
- 接続中・LIVE・再接続中は接続先の選択・追加・編集・削除、方向・解像度・FPS・エンコーダ、ズーム方式 (デバッグ) を
  変更不可にする (ビットレートのみ配信中変更可・即時反映)。
- 方向切替によるActivity再生成でも設定画面・選択中のページ・編集中の接続先を維持する。

### 6.4 縦配信・横配信

| 解像度 | 横配信の出力 | 縦配信の出力 |
|--------|-------------|-------------|
| 360p | 640 x 360 | 360 x 640 |
| 480p | 854 x 480 | 480 x 854 |
| 720p | 1280 x 720 | 720 x 1280 |
| 1080p | 1920 x 1080 | 1080 x 1920 |

- 縦は `rotation=90`、横は `rotation=0` を `prepareVideo` に渡す。幅・高さを手動で交換して二重回転させない。
- 方向は端末保存し、次回起動にも反映する。未設定時は従来の送信形式に合わせて横配信とする。
- 画面は縦配信なら `sensorPortrait`、横配信なら `sensorLandscape`。選択した向きにスマホを持って配信する。
  端末を傾けただけでは送信解像度を変更しない。
- プレビュー開始と配信開始は同じ保存設定 (解像度・FPS・ビットレート・回転・エンコーダ種別) から準備する。
  準備済みの条件と同じなら再準備しないが、方向だけの変更でも再準備する。
- 方向切替では自動的に配信開始しない。配信中の方向変更はUIと操作処理の両方で拒否する。

## 7. 状態仕様

### 7.1 配信状態遷移

```
待機中 → 接続中... → LIVE ─→ 切断 → 待機中
                     ├→ 再接続中... → LIVE (リトライ成功時)
                     └→ 接続失敗 / 認証エラー → 待機中
```

### 7.2 状態と表示・動作の対応

| 状態 | 小さい状態表示 | 主ボタン・動作 |
|------|------------------|----------------|
| 待機中 | 待機中/切断 | 緑の開始、Service停止、タイマー非表示 |
| 接続中 | 接続中... | 赤の停止、Service起動済み、停止操作可 |
| LIVE | LIVE + 経過時間・統計 | 赤の停止、Service起動中、Toast「配信開始!」 |
| 再接続中 | 再接続中... (理由) | 赤の停止、5秒間隔で最大10回自動リトライ、古い統計は消去、Toastで通知 |
| 接続失敗/認証エラー | 接続失敗: 理由 / 認証エラー | 緑の開始、RTMP送信・エンコーダ・Service停止、Toastで通知 |

- 配信処理の動作中フラグ (`isStreaming`) とサーバー接続済みフラグ (`isConnected`) を分離し、接続成功時だけ小さい状態表示をLIVEにする。
  送信統計は接続済みかつスループットが判定できた時だけ更新する。
- ミュート状態と初回接続成功時刻は Controller に保持する。設定画面往復・Activity再生成でリセットしない。
  経過時間は単調時計 (`elapsedRealtime`) を使い、再接続待ち時間も含めて継続し、停止時にリセットする。
  ミュート状態はエンジン再生成時にも引き継ぐ。
- 配信停止と失敗確定は共通処理で送信本体を停止・解放する。後着の切断通知で失敗理由を上書きしない。
  終了済みエンジンは再利用せず、世代番号で古い接続通知を捨てて次回配信に影響しないようにする。

### 7.3 配信本体の寿命

- Controller はApplication Contextを使うプロセス単位の共有インスタンスとし、Activityの `onDestroy` では解放しない。
- 画面はプレビューSurfaceだけを着脱する。設定画面への移動やダークモード変更によるActivity再生成では、配信を継続する。
- 通知の「停止」も同じ Controller の停止処理を呼ぶ。停止時はカメラ・マイクを解放し、
  配信画面が表示されている場合はプレビューを再準備して表示する。
- 非配信時にSurfaceが破棄・解放された場合はエンジンも解放し、画面復帰時に再準備する。
- Serviceは `START_NOT_STICKY`。プロセス終了後に通知だけを復活させたり、配信を自動再開したりしない。
  Service が OS に終了された場合は、通知だけ消えて送信が残らないよう Controller の配信も停止する
  (開始時の世代番号で照合し、古い Service の終了では止めない)。配信中でないのに Service が起動された場合は即終了する。
- 通知チャンネルは `Live streaming` (重要度: 低)。本文は「RTMP配信処理中 (接続・再接続を含む)。タップでアプリに戻る」。

### 7.4 エラーハンドリング

- URL形式不正: 配信開始せず、左上の状態表示に「配信先URLが不正です」を出す
- 接続失敗: 自動リトライ (上限後は停止・理由表示)
- 認証エラー: 即停止
- カメラ/マイク権限なし: プレビュー開始せず、起動時に権限要求ダイアログ。拒否時は Toast で案内
- エンコード設定失敗 (prepare失敗): 状態表示に「映像・音声の設定に失敗しました。設定を確認してください」を出し、Toast通知して開始しない
- カメラエラー・切断・切替タイムアウト: プレビューを未準備に戻して理由を表示。配信中なら配信を停止する

## 8. 権限仕様

| 権限 | 用途 | 必須 |
|------|------|------|
| CAMERA | 映像取得 | ○ |
| RECORD_AUDIO | 音声取得 | ○ |
| INTERNET | RTMP送信 | ○ (インストール時) |
| MODIFY_AUDIO_SETTINGS | マイク入力 (ライブラリ用) | ○ (宣言のみ) |
| POST_NOTIFICATIONS | 配信中通知 (API 33+) | 任意 (なければ通知のみ出ない) |
| FOREGROUND_SERVICE / FOREGROUND_SERVICE_CAMERA / FOREGROUND_SERVICE_MICROPHONE | 常駐配信 (`foregroundServiceType="camera|microphone"`) | ○ (宣言のみ) |
| WAKE_LOCK | 配信中のスリープ抑止 | 任意 (宣言のみ。アプリ側では明示的に取得しない) |

起動時にカメラ・マイク (+ API 33 以上では通知) をまとめて要求する。
カメラ・マイクの必須2権限が揃えばプレビューを開始する。通知権限だけの拒否は開始を妨げず、
カメラ/マイク権限不足の案内も表示しない。

## 9. 設定保存仕様

SharedPreferences `genkai_broadcaster` に保存:

| キー | 内容 | 既定値 |
|------|------|--------|
| destinations | 接続先一覧 (JSON配列: id / name / server / key) | 1件 (`PeerCast Gateway`, `rtmp://pcgw.pgw.jp/live`, キー空) |
| active_destination | 選択中の接続先 id | 先頭の接続先 (保存済み id が一覧に無い場合も先頭) |
| res_index | 解像度選択 (0/1/2/3) | 2 (720p)。範囲外は範囲内へ丸める |
| bitrate_kbps | ビットレート | 3000 |
| video_fps | フレームレート (15/24/30/60) | 30。選択肢にない値は既定値へ戻す |
| stream_portrait | 縦配信かどうか (Boolean) | false (横配信) |
| software_encoder | ソフトウェアエンコーダを使うか (Boolean) | true (互換) |

旧キーからの移行は `destinations` が無い時だけ行う。旧 `rtmp_server` + `stream_key`、
それも無ければ旧 `rtmp_url` (最後の `/` で server / key に分割)、どちらも無ければ既定サーバー + 空キーを
`PeerCast Gateway` として1件目の接続先に取り込み、旧キー3つ (`rtmp_url` / `rtmp_server` / `stream_key`) を削除する。
設定表示と接続URLの組み立ては同じ読み込み関数を使い、編集・保存なしでも移行値で配信開始できる。

## 10. 既知の注意・制約

- 古いデコーダーではスマホのH.264映像を再生できない場合がある。接続先と視聴環境ごとの互換性を確認する。
- 単一RTMPコネクションのため、モバイル回線の瞬断時は自動再接続までの間、受け側が切断表示になる。
- 配信中に縦横比は変更できない。停止して方向を選び直し、再度開始する。
- タブレットやマルチウィンドウではOSが画面方向の固定要求を無視する場合がある。送信解像度は選択設定を維持する。
- 配信中の画面消灯はアプリ側で抑止しない (WAKE_LOCK を明示取得していない)。

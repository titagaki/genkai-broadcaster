# Hoge Broadcaster 仕様書 (v0.1.0)

PeerCast向け Android RTMP配信アプリの仕様定義。
実装の基準とし、仕様変更時は本書を更新する。

- 対象バージョン: v0.1.0 (初期MVP)
- 最終更新: 2026-09-07

## 1. 概要・目的

スマートフォンのカメラ映像を PeerCast (PeerCastStation / PeerCast Gateway) へ
RTMP push で配信するための Android アプリ。

- メイン用途: PeerCast 配信 (野外・IRL等のスマホ起点配信)
- 方針: 余計な機能を持たせず「起動→URL/キー入力→配信開始」の最短動線に絞る
- 非目標: SRT 配信、チャット表示、OBS連携、マルチプラットフォーム同時配信 (対象外)

## 2. スコープ

### 2.1 対応 (MVP)

| # | 機能 | 概要 |
|---|------|------|
| F-01 | カメラプレビュー | 送信解像度の比率でフレーム全体を表示 |
| F-02 | RTMP配信 開始/停止 | サーバーURL + ストリームキー指定で push |
| F-03 | 配信先プリセット | Gateway / 自宅Station例をワンタップ入力 |
| F-04 | 解像度選択 | 480p / 720p / 1080p |
| F-05 | ビットレート調整 | 800〜8000 kbps、配信中の on-the-fly 変更可 |
| F-06 | カメラ切替 | 前後カメラ切替 (配信中可) |
| F-07 | マイクミュート | 配信中のミュート切替 |
| F-08 | 自動再接続 | 切断時に5秒間隔・最大10回リトライ |
| F-09 | ステータス表示 | LIVEバッジ、経過時間、送信ビットレート |
| F-10 | 設定保存 | URL・キー・解像度・ビットレートを端末保存 |
| F-11 | バックグラウンド継続 | ForegroundService + 通知 (停止ボタン付き) |
| F-12 | 背面レンズ選択 | 複数背面カメラを画角表示 (例 26°/71°/97°) で選択 |
| F-13 | 音量メーター | マイク入力レベルを10セグメントで表示 |
| F-14 | 電池残量表示 | 上部バーに残量% + 充電状態を表示 |
| F-15 | 縦配信・横配信切替 | 停止中に縦長 (9:16) / 横長 (16:9) を選択、画面の向きも連動 |

### 2.2 非対応 (対象外)

- SRT / RTSP / WHIP 等、RTMP 以外の配信プロトコル
- チャット・コメント表示、ブラウザソース/オーバーレイ (将来候補あり)
- 配信中の出力解像度・縦横比の変更 (切替には配信停止が必要)

## 4. 技術スタック

| 層 | 採用 |
|----|------|
| 言語 | Kotlin |
| UI | Jetpack Compose (Material3) + `AndroidView` 内 `SurfaceView` |
| 配信エンジン | RootEncoder `library:2.8.1` の `GenericStream` (Camera2ソース) |
| 常駐化 | `StreamService` (foregroundServiceType `camera\|microphone`) |
| 設定保存 | SharedPreferences (`hoge_broadcaster`) |
| 依存取得 | JitPack (`com.github.pedroSG94.RootEncoder`) |

エンコードは H.264 (映像) + AAC-LC (音声) に固定し、
PeerCast の FLV 受け・古いPCプレーヤーとの互換性を優先する。
コーデック選択UIは持たない。

| 項目 | 設定 | 備考 |
|------|------|------|
| 映像コーデック | H.264 (`VideoCodec.H264` を明示) | |
| プロファイル | Constrained Baseline (`AVCProfileConstrainedBaseline`) | Bフレームなし、古いデコーダに最も安全 |
| Level | 解像度・FPSから自動選定 (`H264Level`) | MaxMBPS基準 (720p30→3.1、1080p30→4.0)。過剰なLevelを付けない |
| キーフレーム間隔 | 2秒 (`iFrameInterval=2`) | 途中参加時の復帰を早くする |
| 音声コーデック | AAC-LC (`AudioCodec.AAC` を明示。HE-AACではない) | |
| FPS | 30固定 | |
| 出力方向 | 横: rotation=0 / 縦: rotation=90 | カメラ入力の幅・高さは横長のまま渡し、縦出力時はライブラリがエンコード幅・高さを交換 |

## 5. 配信プロトコル仕様

- 方式: RTMP push のみ。URLスキーム `rtmp://` 以外は受け付けない
- フルURLの組み立て: `サーバーURL(末尾/除去) + "/" + ストリームキー(前後/除去)`
  - キー空欄時はサーバーURLをそのまま使用
- 受け側の前提:
  - PeerCastStation: 先に Station 側で RTMP Source 配信開始 (SEARCHING)
    → 本アプリで push → RECEIVING で本番開始
  - PeerCast Gateway: FLVチャンネル作成後に発行される URL + 4桁キーを入力
    → Gateway 側 Receiving で本番開始
- 再送・ボンディング等の回線対策は持たない (単一RTMPコネクション)

## 6. 画面仕様

画面は「配信画面」「設定画面」の2画面構成。
黒・ダークグレー基調のカメラ操作UIとし、開始・選択は緑、LIVE・停止・ミュートは赤系で区別する。
プレビューと操作領域を分離し、設定類は右上の歯車から開く設定画面にまとめる。

### 6.1 配信画面レイアウト

```
縦画面
+----------------------------------+
| LIVE 00:00          電池% [設定] |
| 720 x 1280 / 30 fps / 送信統計   |
|                                  |
|   (縦長フレーム全体のプレビュー) |
|                                  |
| 配信方向 [縦 9:16] [横 16:9]     |
| [カメラ]  [ライト]  [マイク]     |
|          [配信を開始/停止]       |
+----------------------------------+

横画面
+--------------------------------------------------+
| LIVE 00:00 / 解像度 / 統計          電池% [設定] |
|                                  | 配信方向     |
| (横長フレーム全体のプレビュー)    | [縦] [横]    |
|                                  | カメラ等操作 |
|                                  | [開始/停止]  |
+--------------------------------------------------+
```

### 6.2 配信画面UI要素仕様

- プレビュー: `SurfaceView` を送信映像と同じ縦横比で中央に収める。引き伸ばしや画面を埋めるための切り抜きはしない。
- プレビュー左上に選択中の配信方向、左下に音量メーター (10セグメント、ミュート時は消灯) を表示。
- 未準備時は案内を表示し、必須権限がなければ権限要求ボタンを表示。プレビュー準備前は配信開始を無効にする。
- 上部はLIVE/接続状態・経過時間、実際の送信解像度・FPS・送信統計、電池残量、右端の設定ボタン (48dp)。
- 状態文と統計は可変幅・1行省略表示にし、長い失敗理由でも設定ボタンの領域を確保する。
- 操作パネルは縦画面では下部、横長の表示領域では右側に配置。操作項目は必要に応じてスクロールし、開始/停止ボタンはパネル下部に固定する。
- 配信方向 `[縦 9:16] [横 16:9]` は停止中のみ選択可。接続中・再接続中もロックする。
- カメラボタンは現在の前後をラベルで示し、ボトムシートから前面・背面レンズを選ぶ2段階操作。
  レンズ列挙失敗時は前面/背面の2択。ボトムシートもスクロールできる。
- ライト・マイクはアイコンとON/OFFラベルを併用。前面カメラではライト操作を無効にする。
- 配信開始は緑の横長ボタン、停止は赤。接続中・再接続中も停止操作は可能。
- 不正URL等の注意文はボタン下に最大2行で表示。システムバー・画面切り欠きの安全領域を避ける。

### 6.3 設定画面UI要素仕様

- タイトルバー (戻るボタン + 「配信設定」 + 自動保存の案内)。端末の戻るボタンでも配信画面に戻る。
- 配信先・映像・権限と接続準備の3セクションをカードで分け、縦スクロールで表示する。
- 配信先: RTMPサーバーURL、ストリームキー、プリセット (`Gateway` / `自宅Station例`)。
  キーは既定でマスクし、表示/非表示を切替可能。
- 映像: 配信方向の選択、実際の出力寸法を併記した解像度ドロップダウン、ビットレートスライダー (800〜8000 kbps)。
- 権限再確認ボタン、PeerCast向け説明文。ソフトキーボード表示時も入力欄へスクロールできる。
- 接続中・LIVE・再接続中はサーバーURL・キー・方向・解像度を変更不可 (ビットレートのみ配信中変更可・即時反映)。
- 方向切替によるActivity再生成でも設定画面を維持する。

### 6.4 縦配信・横配信

| 解像度 | 横配信の出力 | 縦配信の出力 |
|--------|-------------|-------------|
| 480p | 854 x 480 | 480 x 854 |
| 720p | 1280 x 720 | 720 x 1280 |
| 1080p | 1920 x 1080 | 1080 x 1920 |

- 縦は `rotation=90`、横は `rotation=0` を `prepareVideo` に渡す。幅・高さを手動で交換して二重回転させない。
- 方向は端末保存し、次回起動にも反映する。未設定時は従来の送信形式に合わせて横配信とする。
- 画面は縦配信なら `sensorPortrait`、横配信なら `sensorLandscape`。選択した向きにスマホを持って配信する。
  端末を傾けただけでは送信解像度を変更しない。
- プレビュー開始と配信開始は同じ保存設定から準備する。準備済みキーにも回転を含め、方向だけの変更でも再準備する。
- 方向切替では自動的に配信開始しない。配信中の方向変更はUIと操作処理の両方で拒否する。

## 7. 状態仕様

### 7.1 配信状態遷移

```
待機中 → 接続中... → LIVE ─→ 切断 → 待機中
                     ├→ 再接続中... → LIVE (リトライ成功時)
                     └→ 接続失敗 / 認証エラー → 待機中
```

### 7.2 状態と表示・動作の対応

| 状態 | バッジ | 動作 |
|------|--------|------|
| 待機中 | 待機中/切断 | Service停止、タイマー0 |
| 接続中 | 接続中... | Service起動済み、停止操作可 |
| LIVE | LIVE + 経過時間 (赤) | Service起動中、統計表示 |
| 再接続中 | 再接続中... | 5秒間隔で最大10回自動リトライ、停止操作可、古い統計は消去 |
| 接続失敗/認証エラー | 失敗理由 | RTMP送信・エンコーダ・Service停止、Toastで通知 |

- 配信処理の動作中フラグとサーバー接続済みフラグを分離し、接続成功時だけ LIVE と表示する。
- ミュート状態と初回接続成功時刻は Controller に保持する。設定画面往復・Activity再生成でリセットしない。
  経過時間は単調時計 (`elapsedRealtime`) を使い、再接続待ち時間も含めて継続し、停止時にリセットする。
- 配信停止と失敗確定は共通処理で送信本体を停止・解放する。後着の切断通知で失敗理由を上書きしない。
  終了済みエンジンは再利用せず、古い接続通知が次回配信に影響しないようにする。

### 7.3 配信本体の寿命

- Controller はApplication Contextを使うプロセス単位の共有インスタンスとし、Activityの `onDestroy` では解放しない。
- 画面はプレビューSurfaceだけを着脱する。設定画面への移動やダークモード変更によるActivity再生成では、配信を継続する。
- 通知の「停止」も同じ Controller の停止処理を呼ぶ。バックグラウンド停止時はカメラ・マイクを解放する。
  配信画面が表示されている場合は、停止後もプレビューを表示する。
- 非配信時にSurfaceが破棄・解放された場合はエンジンも解放し、画面復帰時に再準備する。
- Serviceは `START_NOT_STICKY`。プロセス終了後に通知だけを復活させたり、配信を自動再開したりしない。

### 7.4 エラーハンドリング

- URL形式不正: 配信開始しない + 赤字メッセージ
- 接続失敗: 自動リトライ (上限後は停止・理由表示)
- 認証エラー: 即停止
- カメラ/マイク権限なし: プレビュー開始せず、権限要求ダイアログ
- エンコード設定失敗 (prepare失敗): Toast通知して開始しない

## 8. 権限仕様

| 権限 | 用途 | 必須 |
|------|------|------|
| CAMERA | 映像取得 | ○ |
| RECORD_AUDIO | 音声取得 | ○ |
| INTERNET | RTMP送信 | ○ (インストール時) |
| POST_NOTIFICATIONS | 配信中通知 (API 33+) | 任意 (なければ通知のみ出ない) |
| FOREGROUND_SERVICE / CAMERA / MICROPHONE | 常駐配信 | ○ (宣言のみ) |
| WAKE_LOCK | 配信中のスリープ抑止 | 任意 |

カメラ・マイクの必須2権限が揃えばプレビューを開始する。通知権限だけの拒否は開始を妨げず、
カメラ/マイク権限不足の案内も表示しない。

## 9. 設定保存仕様

SharedPreferences `hoge_broadcaster` に保存:

| キー | 内容 | 既定値 |
|------|------|--------|
| rtmp_server | サーバーURL | `rtmp://pcgw.pgw.jp/live` |
| stream_key | ストリームキー | (空) |
| res_index | 解像度選択 (0/1/2) | 1 (720p) |
| bitrate_kbps | ビットレート | 3000 |
| stream_portrait | 縦配信かどうか (Boolean) | false (横配信) |

旧版キー `rtmp_url` が残っている場合は接続設定の初回読み込み時に server/key へ分割移行し、旧キーを削除する。
既存の新キーは上書きせず、不足している項目だけ補完する。
設定表示と接続URLの組み立ては同じ読み込み関数を使い、編集・保存なしでも移行値で配信開始できる。

## 10. ファイル構成 (保守性のための層分離)

```
hoge-broadcaster/
├── settings.gradle.kts / build.gradle.kts / gradle.properties
├── gradle/wrapper/gradle-wrapper.properties
├── README.md
├── docs/
│   └── spec.md (本書)
└── app/
    ├── build.gradle.kts
    ├── proguard-rules.pro
    └── src/main/
        ├── AndroidManifest.xml
        └── java/com/example/hogebroadcaster/
            ├── MainActivity.kt     (入口: 生成・権限・表示のみ。ロジック禁止)
            ├── StreamService.kt    (foreground keep-alive + 通知)
            ├── streamer/           (配信ドメイン層。Android UIに依存しない)
            │   ├── StreamConfig.kt     (定数の一元管理)
            │   ├── StreamPrefs.kt      (設定の読み書き集約)
            │   ├── StreamController.kt (プロセス共有・GenericStream保持・状態管理・配信操作・再接続)
            │   ├── CameraLenses.kt     (レンズ列挙・画角算出)
            │   └── LevelMeterEffect.kt (マイクレベル観測用素通しエフェクト)
            ├── system/             (端末情報層)
            │   └── BatteryMonitor.kt   (電池残量取得)
            └── ui/                 (表示層。エンコーダAPIを直接叩かない)
                ├── AppRoot.kt          (2画面の遷移管理)
                ├── StreamScreen.kt     (縦横対応の配信画面)
                ├── SettingsScreen.kt   (設定画面)
                └── components.kt       (共有小部品)
```

層ルール:
- UI層 → streamer層は `StreamController` / `StreamPrefs` / `StreamConfig` 経由のみ
- 定数は `StreamConfig` に集約し、マジックナンバーを書かない
- 設定キー文字列は `StreamPrefs` 外に書かない

## 11. ビルド・実行手順

1. Android Studio でリポジトリルートを開く
2. Gradle sync (RootEncoder 2.8.1 を JitPack から取得)
3. 実機を選択して Run
4. 初回起動でカメラ・マイク権限を許可

## 12. 既知の注意・制約

- 一部の古いPCプレーヤー (PCRPlayer既定設定等) でスマホエンコード映像が再生できない場合がある。
  視聴側は VLC / MPV / PeerstPlayer を推奨 (Gateway公式ヘルプの互換表に準拠)。
- 単一RTMPコネクションのため、モバイル回線の瞬断時は自動再接続までの間、受け側が切断表示になる。
- 配信中に縦横比は変更できない。停止して方向を選び直し、再度開始する。
- タブレットやマルチウィンドウではOSが画面方向の固定要求を無視する場合がある。送信解像度は選択設定を維持する。

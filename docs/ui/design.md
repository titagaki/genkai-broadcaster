# UI設計判断

- 最終更新: 2026-09-13
- 状態: 本書の判断はすべて実装済み・実機確認済み
- 現在の画面構成と部品は [現在のUI仕様](current.md)、振る舞いの正本は [製品仕様](../product/spec.md)

この文書には「なぜこの形にしたか」だけを記録する。何がどこにあるかは current.md、どう動くかは spec.md に書く。
UI を変えるときは、ここに判断と理由を追記してから実装し、current.md と spec.md を更新する。

## 1. 画面の基本構成: プレビュー全面 + 操作帯

経緯:

- 初期実装はプレビューと操作パネルを上下に分割していたが、プレビューが小さく、配信中に見たい映像が犠牲になっていた。
- 2026-09-07 に全面プレビュー + 周辺オーバーレイへ変更した (IRL Pro / Moblin の構成を参考)。
- 2026-09-12 に「操作が画面にちらばる」ため見直し、操作 (カメラ・倍率、配信開始、マイク) をスタジアム形の操作帯に
  1か所へまとめ、プレビューとは重ねない構成にした。情報表示・設定・音量メーターは引き続きプレビューへ重ねる。

参考にした構成と、それぞれから採った要素:

| 構成 | 採った要素 | 採らなかった理由 |
|------|-----------|----------------|
| IRL Pro 寄り (周辺の監視情報・レンズ操作) | 基本方針。情報を小さく周辺へ寄せる、レンズ選択 | — |
| Moblin 寄り (全面プレビューに周辺操作を重ねる) | 情報表示のオーバーレイ | 操作まで映像に重ねると散らばって見える |
| 標準カメラ寄り (下部の大きな主ボタン) | 主操作を下 (横持ちでは右) に置く | 配信情報の置き場が別途必要になる |
| パネル分離 (プレビューと操作を分ける) | 操作だけを帯として分離 | 全面を分けるとプレビューが小さい |

判断:

- 情報はプレビューに重ね、操作だけを帯に分離する。誤操作しにくく、映像の中央は空く。
- 帯は矩形パネルではなくスタジアム形 (平行線 + 両端の半円) にし、映像との境界を柔らかくする。厚みは最小限に保つ。
- 縦配信は下に横長、横配信は右に縦長の帯。端末の向きは配信方向に固定しているので、持ち方と帯の位置が常に一致する。
- 帯は3等分したスロットに置き、配信ボタンを帯の中心に揃える。`SpaceEvenly` だとピル型セレクターの幅に
  引きずられて中央がずれるため。
- 画面高さ 400dp 未満 (小さい端末の横持ち) では丸ボタンを 44dp に縮め、補助ラベルを隠して帯の厚みを抑える。

## 2. 配信開始・停止・マイク

| 項目 | 判断 | 理由 |
|------|------|------|
| 形 | 円形 | 設定・マイクと形を揃え、帯の半円と馴染む |
| 位置 | 帯の中央 | 主操作を常に同じ場所に。縦持ちでは親指の届く下中央 |
| 大きさ | マイクと同じ 52dp | 大きな主ボタンにせず、色で主操作を示す。帯を厚くしない |
| 色 | 開始は緑、停止は赤 | 色と表示内容だけで待機中か配信処理中か判断できるようにする |
| ラベル | アイコン + 小さい文字 (`配信開始` / `配信停止`、`ON` / `OFF`) | アイコンだけでは開始・停止の取り違えが起きる |
| マイク | ON/OFF とも丸ボタン。ミュート中は赤 | 配信ボタンと同列に並べ、赤で「止まっている」ことを示す |
| ライト | 持たない | 配信用途で使わないため機能ごと削除 |

状態の意味は色に依存させる。大きな `待機中` / `LIVE` / `切断` バッジは置かず、状態文は解像度・FPS と同じ小さな補助情報にする。

- 開始ボタンを押した直後は `接続中` で、まだ LIVE ではない。
- 接続成功後だけ `LIVE` と表示する。
- 再接続中は LIVE 表示にしないが、停止操作は常に残す。

## 3. カメラ・レンズ・ズーム

| 項目 | 判断 | 理由 |
|------|------|------|
| カメラ面 | `FRONT` / `BACK` を直接選択 | トグルだと現在どちらかを表示に頼ることになる |
| セレクター | `BACK・1x` 形式のピル型ボタン。押すと `CAMERA` / `ZOOM` の2行ポップアップ | 1つの部品でカメラ面と倍率の両方を示し、帯の1スロットに収まる |
| 倍率表記 | 標準画角を `1x` として正規化 | `71°` のような画角やカメラ名より、一般的なカメラアプリの表記に合わせる |
| ズーム | ピンチで連続変更 | スライダーは映像を隠す。プリセットはポップアップ側で提供する |
| 内部方式 | 論理マルチカメラ / 物理レンズ固定 / `自動` を通常UIに出さない | ユーザーには倍率だけで十分。診断はデバッグAPKの設定ページに隔離 |
| 重複カメラID | 同じ実レンズ・倍率は1項目にまとめる | 端末によって同じレンズが複数IDで公開されるため |
| フォーカス | 自動のみ | タップフォーカスは未実装 (§6) |

Android 11 以降の論理マルチカメラ対応端末では倍率によるレンズ切替を優先し、それ以外は物理レンズ固定 + デジタルズームへ
フォールバックする。切替の成功判定や失敗時の扱いは spec.md §6.2 に置く。

## 4. 常時表示する情報

- 状態・解像度・FPS を左上1行目、経過時間・送信統計・電池を2行目に、小さい文字で重ねる。
  以前のヘッダー領域を廃止してプレビューを広げるため。
- 電池残量は配信中に一番気になる端末側の情報なので統計と同じ行に置く。
- 音量メーターは左下に下端に沿わせて置き、配信前から動かす。開始前にマイクが生きているか確認できるようにする。
- メーター直下に使用中と推定されるマイク種別を出す (2026-09-13)。有線・USB マイクを挿したときに、
  それが使われているか一目で分かるようにする。選択UIは持たない (OS のルーティングに任せる)。
- 縦/横ラベルは配信画面から削除し、設定画面だけで選ぶ。配信中に変えられない設定を配信画面に置かない。
- 接続失敗理由や不正URLの注意も左上の状態文に出し、別のバナーやダイアログにしない。

## 5. 設定画面

- カテゴリ階層 (メニュー → 配信 / 映像 / カメラ / 権限) を採用した。Larix や IRL Pro と同じ構成で、
  1画面に全部を並べるより探しやすい。3階層目は `配信 > 接続先の編集` だけに限定し、他では作らない。
- メニュー行に現在値の要約を出す。ページを開かなくても設定状態が分かるようにする。
- ビットレートはスライダーではなく数値入力 + `<input type="number">` 風の ∧/∨ ボタン。
  スライダーは 100〜10000 kbps の範囲で細かい値を狙いにくい。上限・下限の説明文は出さない。
- 解像度は `HD (720p) / 1280 x 720` のように一般名と出力寸法を併記する。`720p` だけでは縦配信時の寸法が分かりにくい。
- 接続先は複数保持して切り替える。プリセットは PeerCast Gateway と Twitch
  (ツイキャス・自宅 PeerCastStation は不要)。「Gateway」ではなく正式名「PeerCast Gateway」を使う。
- 権限ページに接続先ごとの準備案内は置かない (2026-09-13 に削除)。手順は接続ガイド等の文書に置き、アプリ内には持ち込まない。
- エンコーダ選択はズーム方式 (デバッグ) と同じ縦並びのラジオ形式。選択肢が2つで説明文が要るため、セグメントより行形式が読みやすい。
- カメラページはデバッグAPKだけに出す。通常ユーザーに内部方式を見せない (§3)。
- コメントページは提供アプリの選択と表示位置 (上/下) だけ (2026-09-13)。大きさ・秒数の設定は置かない。
  まず固定値で使ってもらい、要望が出てから項目を足す (§6)。上下は最初の実機確認で要望が出たので同日に足した。

## 5b. コメントの焼き込み位置 (2026-09-13)

- 映像の**右側・右揃え**に置き、上下だけ選べる (既定は下)。左下は Compose の音量メーター (M-01) とマイク表示が重なり、
  プレビューで両方読めなくなる。左上は情報表示があるので左は使わない。右上は設定ボタン (52dp) と重なるが、
  配信映像としては上に置きたい場面 (下に字幕や操作帯を写す等) があるので選択肢として残す。
- コメントは Compose の部品ではなく映像側の合成 (RootEncoder のフィルタ) なので、プレビューにもそのまま映る。
  配信に乗るものと見えているものが一致するのは利点として受け入れ、プレビュー専用の表示は作らない。
- 接続状態は情報表示 (I-01/I-02) の 3 行目に入れ、Toast は接続失敗時だけにする。提供アプリの取得エラーは
  繰り返し起きうるので、Toast の連発を避ける。

## 6. 未決事項

- 停止確認 (タップ確認・長押し): 現状は確認なし。誤操作の報告があれば検討する。
- タップフォーカス: 現状は自動のみ。
- 横配信で端末を反対向きに回した場合の扱い: 現状は `sensorLandscape` に任せている。
- 片手操作と両手・横持ち操作のどちらを優先するか: 明示的に決めていない。
- コメントの文字サイズ・表示秒数・左右位置・流れる表示: 現状は固定 (右寄せ・短辺の 1/24・10 秒・5 行)。要望が出たら設定化する。
